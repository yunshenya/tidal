# tidal 第三阶段报告（公开版，2026-10-08，UTC+8）

> 这是公开仓库里的脱敏版本：只包含**公开数据**上的结果和**只用公开数据训练**的模型的数字。凡是用到部署方真实聊天
> （训练或评测）的数字只留在私有报告里，这里只给定性结论。公开数据集不再分发，在它们上面训练的权重也不发布。

## 1. 目标和做了什么

第二阶段的瓶颈是数据：真实数据少，直播和 1:1 流是脚本合成的，也没有真正的音频前端。第三阶段：

1. 在 HF 上筛选许可证明确的公开数据集（清单、许可证、跳过原因见 [phase3_datasets.md](phase3_datasets.md)），
   写了下载器、转换器（`tidal/public_data/`），统一转成身份无关的事件流（时间、相对角色、模态、内容）。
2. 公开数据上预训练（VAP 投影自监督 + 多任务头），再在私有真实数据上微调和评测（同一套留出和时间切分、块自助法 CI）。
3. 用真实直播聊天（Twitch、NASA Artemis 直播评论、B 站弹幕）重做留一场景（LOSO）。
4. 音频前端：40 维 log-mel → 因果深度卷积 → GRU(96)，约 7.3 万参数，流式 20 ms 一步；预测双方语音活动、
   VAP 式未来 2 s 语音活动（换人 / 保持）和附和（backchannel）。已接入全双工 tick 循环（`AudioFrontEnd`）。
5. int8 动态量化（ONNX Runtime）的精度和延迟对比。
6. 通用的 `!语料` 对话片段格式解析器（`tidal/corpus_fmt.py`，附虚构示例 `examples/corpus_example.txt`）。

## 2. 音频前端（全部是公开数据）

块自助法（按会话 / 说话人重采样）95% CI。AUC 在各折内分别计算再按样本数加权平均（每折是不同的模型）。

**MagicData 中文双人分轨（research-only），按说话人对 3 折交叉验证（测试说话人没见过）**，人工分段标签：

| 任务 | n（正例率） | 只用 MagicData | oto 预训练 → MagicData 微调 | oto 零样本 | LR（韵律 + 时长特征） |
|---|---|---|---|---|---|
| 对方说完 200 ms 时：我接（换人）还是对方继续 | 1,284（0.42） | ROC-AUC 0.677 | **0.710** | 0.611 | 0.652 |
| 对方说话时：0.5 s 内我会附和吗 | 164,211（0.004） | 0.611 | **0.720** | 0.468 | 0.689 |

- 换人：oto 预训练 + 微调 − 只用 MagicData = +0.032 [−0.006, +0.069]；− LR = +0.056 [−0.002, +0.115]（都跨 0）。
- 附和：oto 预训练 + 微调 − 只用 MagicData = **+0.115 [+0.086, +0.148]**；− LR = +0.028 [−0.009, +0.063]（跨 0）。
  只用 MagicData 的模型在附和上显著不如 LR（−0.087 [−0.140, −0.036]）。
- 结论：英文全双工语音预训练对中文附和有明显帮助；对换人有正向趋势但不显著；零样本跨语言迁移不行。

**otoSpeech 全双工英文（CC BY 4.0，8/61 个分片中的 60 场会话，约 16 小时；按会话 72/8/20 切分）**，
标签来自能量 VAD（这个数据没有转写），附和是声学代理标签（≤1 s、完全落在对方语音内部的短段）：

| 任务 | n | 模型 | LR | 模型 − LR |
|---|---|---|---|---|
| 换人 / 保持 | 3,653 | 0.774 | 0.656 | **+0.116 [+0.088, +0.144]** |
| 附和（代理） | 86,730 | 0.698 | 0.620 | **+0.077 [+0.054, +0.104]** |

**Krisp 轮次测试集（只做评测；许可证禁止训练，在上面没有拟合或调参任何东西）**：2,730 段英文单声道片段，
人工标注 shift / hold，片段以一段静默结束。

| 打分 | ROC-AUC | PR-AUC |
|---|---|---|
| 片段末尾静默时长（不拟合，直接当分数） | **0.839** | 0.745 |
| MagicData 折模型（中文训练） | 0.826 | 0.744 |
| oto 模型（英文训练） | 0.741 | 0.663 |

两者都显著好于随机，但都没有超过"静默越长越可能换人"这个零参数基线（oto − 静默 = −0.096 [−0.165, −0.029]，
MagicData 模型 − 静默 = −0.013 [−0.048, +0.025]）。oto 模型的分数受能量 VAD 标签和单声道输入（自己那一路是静音）影响。

## 3. 文字 / 事件流（定性；数字在私有报告）

- **真实留出数据**：预注册的选择规则（按真实 val loss 选配置，再选该配置 val 最好的种子）选中了"公开数据预训练 →
  真实 + LLM 合成数据微调"。和第二阶段主模型比，各头有升有降，大部分 95% CI 跨 0；个别头显著变好或变差，
  没有一致的提升。结论不变：**没有稳定、显著地超过最强基线**。
- **留一场景（真实直播）**：训练里没有直播数据时，迁移到真实 Twitch 直播聊天的效果混合（EOT、recheck 好于 LR，
  续话、说/等/不说差于 LR）；加入 Twitch 训练流后，VAP 投影在 Twitch 和中文 B 站弹幕上都显著好于同数据的 LR，
  但"该不该说"仍然不如 LR。没有主播的高并发直播评论（Artemis）上，所有模型的 VAP 投影都不稳定（CI 很宽）。
- **只用公开数据训练的模型 → "回应哪条消息"**（Telegram 测试集上 1,525 次带金标回复链的回复，平均 19.4 个候选）：
  命中率 0.475，"总是回最近一条" 0.447，差 **+0.029 [+0.003, +0.055]**（按会话块自助）。IRC 测试集在当前视角
  构造下没有可用的样例。

## 4. 延迟和量化

**全双工 tick 循环 + 真实音频流**（单线程，PyTorch eager；每 tick 输入 2 × 100 ms 的 16 kHz PCM → log-mel →
音频编码器 5 步 → 事件编码器 → tick GRU）：

| 每 tick 到达的事件 | p50 | p95 | 其中音频前端 p50 | 10 Hz 下的实时系数（p95） |
|---|---|---|---|---|
| 0 | 0.92 ms | 1.34 ms | 0.69 ms | 0.013 |
| 1 | 1.42 ms | 1.89 ms | 0.67 ms | 0.019 |
| 5 | 3.69 ms | 4.91 ms | 0.70 ms | 0.049 |
| 20 | 18.9 ms | 25.6 ms | 0.65 ms | 0.256 |

音频前端每 100 ms 只多花约 0.7 ms。见 `reports/duplex_bench_audio.json`。

**int8 动态量化**（只用公开数据训练的模型，公开测试集 4,000 个窗口）：模型文件 1.96 MB → 1.74 MB（只有线性层被量化，
GRU 保持 fp32），单线程 batch=1 延迟 p50 1.03 → 0.98 ms，基本不变。各头主指标的变化都在 ±0.02 以内，
EOT / 续话 / 接话的决策一致率 ≥ 99.5%；recheck 的 macro-F1 显著下降 0.015（CI [−0.020, −0.009]）。
量化在这个尺寸上收益很小。

## 5. 弱点

- 音频：MagicData 只有 27 场、3 对说话人，分段粗（中位数 6.6 s）；oto 的标签来自能量 VAD，附和是代理标签；
  Krisp 上没超过静默时长基线；音频前端还没接入 tick 策略的训练（tick 策略仍只在脚本模拟器上训练，
  音频的换人 / 附和分数目前是直通 + 简单阈值提示）。
- 中文直播：B 站弹幕是点播视频的弹幕（观众在不同时间发、按视频时间对齐），不是直播间实时弹幕，没有发言人 ID，
  也没有主播，只能评测时间节奏 / VAP 投影。没有找到许可证清楚的中文直播间实时弹幕数据。
- DanmakuTPP 卡片没有写许可证（gated），按 research-only 处理。
- 蒸馏没做。
