## 官方题库实际在测什么

stage 0 官方题库 360 题，6 个技能：`where` 64、`color` 48、`who` 64、`attribute` 48、`count` 64、`handoff` 72。每题都是三行：一句事实，一行 `问：…？`，一行 `答：`。不同的问句行是 99 句。每题只有一个金答案。

几乎照抄原句的是前五类，不是全部。`color` 48 题是去掉事实末尾的「的。」；`where`、`who` 全部，以及 `attribute` 的 42/48 题，是去掉句末「。」；`count` 64 题是去掉句首「这里」再去掉「。」。`attribute` 另有 6 题不是原句子串：事实是「教室的灯灭了。」，答案是「教室的灯没亮」。`handoff` 72 题全部不是抽取，而是改写，例如「爸爸把水杯给了弟弟。」对「弟弟拿着爸爸给的水杯」。

`where` / `color` 短、可抄，终局 exact 主要落在这里。`who` 同样是去掉句号的抽取，但种子极不稳：`scratch_final` 是 11/64、58/64、6/64。`count` 要模型把第一字写成「有」，而不是续写「这」；`staged_final` 上 CJK 是 72.19% / 63.12%，first-CJK 是 0。`handoff` 是 10 个 CJK 字的改写，和事实不对齐；不要用 first-CJK 替换它的 exact。

官方过滤器对这套题的整句和 8-gram 丢弃是 0。错位是格式、答案形态和技能覆盖，不是题目泄漏。`staged_final` 在纯 stage 0（权重 [1, 0, 0, 0]）上，任务 exact-match 每次都是 0；可用的 exact 出现在后续阶段混入之后。

## 训练实际在教什么

计数与例子来自「现有数据与评测能否区分能力（离线核对）」，以及同一份 stage 0 `train.jsonl` 的格式核对。stage 0 训练 22409 篇，不是题库这种三行短阅读。格式是 `ticks`、`dialogue`、`continuation`。文本以故事和对话为主。

以「问：」开头的行是 0。「问：」或「问:」出现在 13 篇，「答：」或「答:」出现在 18 篇，probe 标点下同时含「问」和「答」的文档是 1/22409。这 13 / 18 篇几乎都是故事里的叙述，例如「莉莉问她妈妈」，不是题库的框。

技能词在故事和对话里有：630 篇含「在哪里」（同一文件上曾写成 631，重计是 630），476 篇含「什么颜色」。它们不是「问：」问句。含「在谁手里」的是 0。

唯一接近问答的是 46 篇 `substage=qa`，来源 `template_qa_dialogue`，占训练集的 0.21%。它们用 `<user>` / `<bot>`，不是「问：」/「答：」，而且通常是闭卷：事实在 bot 那一句里。颜色问句是「这是什么颜色？」，计数问句是「有几个…？」。46 篇里没有「在哪里」，没有「谁在…」，没有「现在怎么样」，没有「在谁手里」。即便是颜色和计数，题面也与官方题库不同：训练是「这是什么颜色？ / 这是白色的灯」，题库是「帽子是白色的。 / 问：帽子是什么颜色？ / 帽子是白色」。

后续阶段有「问：/答：」，但形态仍不完全是官方题库那种开卷短抄。stage 1 的 556 篇里，217 篇以「问：」起行且同时有「答：」，39.0%。问句里含「在哪里」的 24 条，「去了哪里」13 条，含「谁」的 66 条（其中含「谁在」的 32 条）。「什么颜色」「几个」「怎么样」「在谁手里」都是 0。这些问答常常是闭卷。stage 2 的前 200000 篇里，同时含「问：」和「答：」的文档是 1961 篇；以「问：」开头的行是 401 行，其中「什么颜色」6 条、「几个」47 条。出现的问答更杂，也更长。

## 推荐路径

冻结现有 E2 训练集。不把「问：/答：」和几乎照抄原句的答案注入 stage 0。先改的是这套题在 stage 0 上的用法。

具体是三件，顺序已经走到第三件的验收，不是「以后再做」。

第一，公开发表的 stage 0 比较，不用整库整句 exact-match 当头条。用 headline CJK、first-CJK，以及按技能表。headline 继续去掉 `count` 和 `handoff`。`where` 和 `color` 是这套题上会动的抽取切片；`who` 和 `attribute` 要报，但不并成单一头条；`count` 和 `handoff` 留作诊断。stage 2 / 3 比臂继续用 first-CJK 或 CJK，不用整句 exact-match。这一层已经打完，见上面的报道层一节。

第二，当前这套「问：/答：」抽取题，是后期格式 / 迁移测验，不是「只练 stage 0」的结业考，也不是 stage-0-only 的毕业考。题库保留。纯 stage 0 上 exact 为 0，不能读成「stage 0 数据没教会 stage 0 技能」。`random_order` 较高的官方 stage 0 headline（exact 30.80% / 33.04%）按后期格式抬分读，不按课程优越读。

第三，纯 stage 0 窗口上若还需要一条有可能离开地板的任务分，用训练格式诊断库，不把题库格式写进训练。格式是 `<user>` / `<bot>` / `<eot>`，技能跟 stage 0 训练里真正出现过的走。v2 的头条是 32 道开卷：颜色、计数、处所、人物。闭卷颜色和计数只作对照，不进头条。没有 handoff，没有「在谁手里」。这份库不替换官方「问：/答：」题库。题库文件不进本仓库。

不走（A）。把「问：/答：」和几乎照抄的答案注入 stage 0，会让未来的臂去拟合这套题。现有检查点验证不了它有没有用：盘上只有终局 `curriculum.pt`。要知道（A）有没有把「只练 stage 0」打出非零 exact，就必须新跑一条训练。题库答案几乎是原句，注入之后也容易变成近复制测验。

也不把换包装当成与诊断库同等的主路径。把现有 360 题的「问：/答：」换成 `<user>` / `<bot>`，可以以后作为一次廉价的 CPU 敏感性检查。它解释不了 `handoff` 的改写答案，也解释不了 `who` 的种子摆动。诊断库已经按训练框写过一版，不再把换包装做成新的正式题库。

## 改什么，不改什么

已经改过的只有报道：头条、按技能、first-CJK，以及诊断库的分数表。数据文件和官方题库文件没有动。

仍然不改：

- 毕业默认仍是 `mastery_metric=stage_probe`，阈值 0.85，`sustain` 2。`allow_plateau_graduation` 仍开着，`handwritten_gate` 仍关着。不把任务题 exact、CJK 或 first-CJK 接到毕业门上。`probe0_acc` 与任务 CJK 反向，那是已经记录的限制，不是改门的理由。格式对齐还没有通过下面的验收，因此也不另开一条任务掌握门。纯 stage 0 上，官方题库的 exact 和 CJK 都不会抬到能毕业的位置；掌握路径会把 run 留在 stage 0，离线估计已经给过这个结论。
- 现有 E2 训练集不动。不把题库框写进 stage 0。
- 不把诊断库 jsonl 提交进 tidal 或 growbrain。
- 不为了对齐再开一条 coupled、staged、mastery 或 `stage0_only` 训练臂，也不租卡，也不 `--resume`。

## 验收

验收用的就是这 15 份终局检查点上的 CPU 只评测，发生在任何新训练之前。成功不是「分数变高」。

对照当初写下的四条：

1. 诊断库的格式是训练里有的，不再依赖「问：/答：」。在颜色、计数、处所这类训练里出现过的技能上，分数不应再全体贴在 exact 地板上，也不应再出现 `count` 那种 CJK 中高、first-CJK 全 0 的前缀坍缩。若前缀坍缩还在，先修诊断题的答案形态，不要开训练。

   部分成立。v1 整库 exact 是 0–2/32，15 个检查点一共 9 次命中，全在开卷处所或人物；闭卷颜色+计数 exact 是 0/240。v2 把颜色和计数改成开卷之后，开卷 exact 合计 34/480，头条 exact 是 0–8/32，高于 v1 的 0–2/32，仍然低。最高是 `decoupled` seed2 的 8/32（颜色 5、计数 2、处所 1）。`staged_final` seed1 与 `scratch_final` seed0 是 5/32。五个检查点仍是 0/32，包括 `random_order` 的两个种子。闭卷对照 exact 仍是 0/120。闭卷贴地板是预期：上下文里没有事实，stage 0 预训练答不出这些新槽。不把闭卷 exact 读成应当非零的能力分，也不把金答案放宽成「红色的。」或「一个X。」来抬 first-CJK。

   前缀坍缩有所缓解，但没有消失，也不是单向变好。计数的 first-CJK，v1 里 `scratch_final` 与 `random_order` 是 0/8；开卷后 `scratch_final` seed0 / seed2 到 8/8，`random_order` 到 5/8 与 2/8。人物改用「X在做什么？」之后，`staged_final` seed1 与 `random_order` seed1 的 first-CJK 从 0/8 到 7/8。颜色有升有降：`scratch_final` seed0 从 0/8 到 7/8，`decoupled` seed2 从 0/8 到 8/8，`decoupled` seed1 从 8/8 降到 3/8，`growth_only` seed2 的计数从 4/8 降到 0/8。first-CJK 变高常常只是开头对齐了训练框，后面的数字、颜色或名词仍错。处所的「在」与实体分裂还在。因此第 1 条没有过到可以据此开训练的程度。没有继续改金答案去贴各臂的习惯说法。

2. 诊断库上的臂间差，不应再主要跟着「见过多少后期「问：/答：」文档」走。若 `random_order` 仍然只因为后期格式而大幅领先，则诊断库还没有测到 stage 0 数据里的东西。

   这一条的反例没有出现：官方题库上 `random_order` 的 stage 0 headline 优势没有转到训练格式库。v1 上它是 0/32 与 1/32。v2 上两个种子的头条 exact 都是 0/32。这支持「那份优势更像格式曝光」的读法。

   同一条也说明终局分还不能排臂。头条 exact 可以把 `decoupled` seed2 的 8/32、`staged_final` seed1 / `scratch_final` seed0 的 5/32，与五个 0/32 分开；多数臂仍挤在 0–3/32。同一臂的种子摆动很大：`decoupled` 是 0/32 与 8/32，`staged_final` 是 5/32 与 1/32。全体 40 题 CJK 约 55.74%–72.34%，头条 CJK 约 58.85%–79.17%，臂间重叠仍大。终局分不是稳定的臂排序，也还不够解释课程。

3. 官方「问：/答：」题库按迁移测验重打，结论应与报道层重打分相容。

   成立。整库 exact 与 CJK 和原先终局点估计一致。`random_order` 的高 stage 0 headline、`coupled` 仍然差的 headline、`staged_final` 的 exact 几乎全在 `color` / `where`、`count` 的 CJK 中高而 first-CJK 为 0，都与这次重打分同一套数。

4. 没有纯 stage 0 的权重。终局检查点都见过后续阶段。诊断库上的非地板分数不能单独证明「只练 stage 0 就会了」。这一条限制留在报告里，不用一次新的 `stage0_only` 训练去补。

   仍然成立，而且没有被这次打分消掉。

验收只部分成立。第 3 条成立，第 4 条的限制还在。第 2 条排除了「诊断库只是在重测后期「问：/答：」曝光」，但终局分摆动太大，排不了臂。第 1 条只走到「开卷阅读测得动、前缀坍缩未消失」。因此现在不谈最终宽度、只练 stage 0 的训练实验。那要等格式对齐真正站住。数据与评测还没有对齐到可以开实验的程度。

## 为什么现在仍不应开训练或租卡

（A）和任何再跑一条 staged、coupled、mastery 或 `stage0_only` 的臂，都要用新的优化步才能知道有没有用。现有终局检查点做不到这一点。报道层补的是终局按技能和 first-CJK。诊断库补的是训练格式上的终局分。两者都没有纯 stage 0 窗口的权重，诊断库的终局 exact 也不是稳定排序。新臂会继承还没对齐完的评测：官方题库在纯 stage 0 上的 exact 仍会是 0，stage 0 头条仍会被后期格式和 `who` 的种子摆动带着走。掌握毕业的 GPU 跑已经判断过不值得。这次没有改变那个判断。

## 残差

- `who` 的种子摆动还在官方 headline 里。`scratch_final` 是 11/64、58/64、6/64。n=2 或 n=3 撑不住把 exact 当单一头条。
- 官方 `count` 在 `staged_final` 上 first-CJK 为 0、CJK 为 72.19% / 63.12%。这是前缀或格式失败。诊断库把计数改成开卷之后，部分臂的 first-CJK 抬起来了，后面的数字或名词仍常常不对。
- `handoff` 是改写题，不是抽取。训练里也没有「在谁手里」。诊断库没有放这个技能。
- `attribute` 两粒不稳，且有 6 题金答案不是原句（「灯灭了」对「灯没亮」）。
- 仍然没有 stage-1 任务题库。
- stage 2 / 3 的整句 exact-match 仍是地板。first-CJK 有梯度，也高度集中在技能上，不能当成精细的课程差。
- `probe0_acc` 仍与任务分反向，不能当掌握，也不能当毕业代理。
- 没有中途权重，终局按技能表不能回答「第一次和第二次毕业各自抬起了哪个技能」。
- 诊断库题量小。闭卷对照 8 题，每个开卷技能 8 题。8/32 不是稳定的能力分。计分仍是 teacher-forced，不是自由生成的整句匹配。

## 还没做、本仓库也不做的

growbrain 里已提交的任务题 `manifest.json` 仍是 `train_filter.checked=false`。同阶段 0 丢弃是 2026-11-10 量的，跨阶段 12 对 0 丢弃已经写在「现有数据与评测能否区分能力（离线核对）」。要填的是 filter 块，用相对路径，不要带绝对训练路径。那份 manifest 不在 tidal 里。本 PR 不改它，也不改 jsonl。
