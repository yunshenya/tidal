# tidal 架构与路线图

> 目标：做一个**原生多模态**（视频、图像、音乐、语音、文本）、**会判断什么时候该说话、什么时候该沉默**的极小模型。它只用 CPU，常驻参数 ≤ 2M。
> 本文给出具体设计，并把每一项现代建模技术对应到 tidal 的某个组件上，逐项标注状态：✅ 已实现 · 🚧 进行中 · 📋 计划中。
> 状态以本仓库代码为准，不夸大。**目前真正跑通的只有"时间节奏 + 文本"两路输入，外加内容无关的消息类型元数据。图像、视频、音频的前端都还是计划。**
> 调研和差距分析见 [related-work.md](related-work.md)；第一阶段的结果见 [../reports/phase1.md](../reports/phase1.md)。

## 1. 总体结构

```
   每个事件（一条消息 / 一段音频帧窗口 / 一个视频片段）
   ┌────────────────────────────────────────────────────────────────────────┐
   │ 时间 / 角色特征     → Linear ─┐                                       │
   │ 消息类型元数据 meta  → Linear ─┤                                       │
   │ 文本   (bge 冻结 / 字节 BPE) → proj ─┤                                │
   │ 图像   (patch/conv stem)     → proj ─┼─ Σ + 模态掩码 → LayerNorm → token│
   │ 视频   (帧采样 → 图像 stem → 时间池化) ─┤                              │
   │ 音频   (log-mel → 因果 conv → 小 GRU/SSM；语音 + 音乐) ─┘              │
   └────────────────────────────────────────────────────────────────────────┘
                     │  每个事件一个 token（d = 128）
                     ▼
   共享因果时序编码器：GRU（已实现）/ 因果 Transformer + RoPE / SSM（计划）
   流式推理：新事件到来时，只基于已经发生的事件更新状态
                     │
                     ▼
   多任务头：EOT · 续话 · 被叫 · 说/等/不说 · 重检延迟 · 人类接话
             ＋ 计划：附和 / 打断 · 模态理解（这是什么媒体、情绪、事件）
                     │
                     ▼
   校准（温度缩放）→ 不确定性 / 弃权 → 决策层硬规则（被 @ 必须回应、发言预算、深夜静默）
```

代码映射：
- 前端：`tidal/modalities/`，所有前端都实现同一个接口 `FrontEnd`（`dim`、`available()`、`encode()`）；
- 时间特征：`tidal/features.py`；
- 主干和头：`tidal/model.py`；
- 训练：`tidal/train.py`；
- 校准和评测：`tidal/evaluate.py`、`tidal/metrics.py`；
- 导出：`tidal/export.py`；
- 影子模式：`tidal/shadow/`。

缺失的模态在输入端就是"零向量 + 掩码位"，所以主干不需要知道某个事件带了哪些模态。新加一个前端时，只要实现 `FrontEnd` 接口，再在 `model.py` 里加一个投影层。

## 2. 参数预算（常驻 ≤ 2M，CPU 单线程）

| 组件 | 预算 | 现状 |
|---|---|---|
| 时间 / 元数据投影 | < 10k | ✅ 已有时间投影；元数据只在影子模式里记录，还不是模型输入 |
| 文本前端 | 冻结 bge-small-zh int8（约 24M，**不计入常驻预算**，按需调用）；计划换成字节级或小 BPE 嵌入 + 2 层小编码器，约 0.2–0.3M | ✅ bge；📋 自有小文本前端 |
| 图像前端 | patch/conv stem（96–128 px 缩略图，深度可分离卷积或 2 层 patch Transformer），约 0.3M | 📋 |
| 视频前端 | 复用图像 stem，均匀抽 4–8 帧做因果池化，额外约 0.05M | 📋 |
| 音频前端（语音 + 音乐） | 16 kHz、64 维 log-mel、10 ms 帧移 → 因果 conv → 小 GRU/SSM，约 0.3M | 📋 |
| 共享时序主干 | 0.5–0.8M（现在的 GRU 是 0.55M） | ✅ GRU / 因果 Transformer |
| 多任务头 | 约 0.1M | ✅ 6 个头 |

大教师模型只在**离线**环境下使用（见 §3 的蒸馏），从不常驻，也不参与线上推理。

## 3. 技术 → 组件 → 状态

| 技术 | 在 tidal 里的落点 | 状态 | 说明 |
|---|---|---|---|
| 按模态划分的前端：图像 / 视频帧用 patch 或 conv | `modalities/image.py`、`video.py` | 📋 | 接口已定义，`available()` 返回 False |
| 按模态划分的前端：语音 / 音乐用 log-mel | `modalities/audio.py` | 📋 | 常量（64 mel、16 kHz、10 ms）已定义 |
| 按模态划分的前端：文本 | `modalities/text.py`、`embed.py` | ✅ / 📋 | 现在用冻结的 bge int8；计划换成字节级或小 BPE 的自有前端，以缩小体积、去掉外部依赖 |
| 内容无关的消息类型元数据（图片 / 语音 / 视频 / 文件 / 贴纸 / 表情 / 分享） | `modalities/meta.py`、影子库 `events.media_*` | ✅（采集）/ 📋（作为输入） | 从平台占位符和 CQ 码解析，不读取媒体内容 |
| 共享小主干：GRU | `model.py` kind=gru | ✅ | 2 层，隐藏层 192，0.55M |
| 共享小主干：因果 Transformer | `model.py` kind=tf | ✅（可学习位置编码） | |
| RoPE | `model.py` | 📋 | 替换掉可学习位置编码，方便外推到更长的上下文 |
| SSM / 线性 RNN 主干 | `model.py` | 📋 | 流式友好，状态是常数大小 |
| 跨模态时间融合 | 事件 token 求和 + 模态掩码 | 🚧 | 时间和文本两路已经融合；其余模态等前端做完再接入 |
| 流式 / 因果推理 | `features.py`（因果特征）、`model.py`、`shadow/infer.py` | ✅ | 审计确认：截掉未来事件后特征不变，第 t 位的输出不受 t 之后输入的影响。影子模式逐条消息预测 |
| 多任务头：说 / 等 / 不说、EOT、续话、被叫 | `model.py` HEAD_DIMS | ✅ | 另有重检延迟、人类接话两个辅助头 |
| 多任务头：模态理解（媒体类型、情绪、声学事件） | `model.py` | 📋 | 先用 meta 弱标签，再用教师蒸馏 |
| 自监督：掩码事件建模 / VAP 式的未来活动预测 | `train.py` | 📋 | 可以在所有只有时间信息的事件上做预训练 |
| 自监督：跨模态对比对齐 | 前端 + 投影层 | 📋 | 图文、音文的 InfoNCE，只用公开数据或合成数据 |
| 知识蒸馏（大教师 → 小学生） | 离线管线 | 📋 | 教师只在离线环境运行，只处理合成数据或非私有数据。需要 API 时只用 tidal 自己的 key，**真实聊天从不发给外部 API** |
| LLM 合成数据增强 | `synth.py`、`synth_clean.py` | ✅ | 有预算上限，提示词里只有抽象的场景描述。第一阶段发现合成数据对节奏类的头有帮助，对"被叫"和"动作"有害 |
| 课程学习 | `train.py` | 📋 | 先合成后真实；先学节奏头，再学决策头 |
| 数据增强（时间抖动、丢弃模态、文本扰动） | `seqdata.py` | 📋 | "丢弃模态"能让模型适应线上缺模态的情况 |
| int8 量化 | `embed.py`（bge 动态 int8） | ✅（文本编码器）/ 📋（主干） | 主干计划做 PTQ / QAT，并和 FP32 做一致性测试 |
| 剪枝 | `model.py` | 📋 | 按头和通道做结构化剪枝 |
| LoRA / adapter | `model.py` | 📋 | 按群或按场景挂小 adapter，主干冻结 |
| 校准 | `evaluate.py` | ✅ | 每个头单独做温度缩放；报告 ECE、Brier 和校准分箱 |
| 不确定性 | `evaluate.py` / `shadow` | 📋 | 小型 seed 集成或 MC dropout；保形预测（conformal） |
| 弃权（abstention） | 决策层 | 📋 | 不确定时交给硬规则或旧策略处理 |
| 离策略修正（IPS） | `train.py` 动作头 | 📋 | 上游的 replay 里有 propensity |
| ONNX 导出 + 一致性测试 | `export.py` | ✅ | 和 PyTorch 的最大差约 2e-7 |
| 与基线的对比评测 | `baselines.py`、`evaluate.py`、`metrics.py` | ✅ | 多数类、间隔阈值、LR、GBDT、单句文本；按"会话 × 小时"分块 bootstrap 求 CI |
| 泄漏审计 | `audit.py` | ✅ | 因果性、可得性泄漏、切分完整性 |
| 影子模式门控（上线前） | `tidal/shadow/` | ✅（基础设施）/ 🚧（积累数据中） | 只记录不执行；**在 CI 显著优于基线之前，不接管任何真实决策** |

## 4. 落地顺序（建议）

1. 🚧 影子模式积累 1–2 周的数据，包括消息类型元数据，然后重新评测 T 和 TS 两个口径。
2. 📋 把 meta 元数据接为模型输入，加上"丢弃模态"增强，再加 IPS 动作头。
3. 📋 音频前端（log-mel + 小因果 conv），用离线教师蒸馏（转写、情绪、声学 EOT），只在公开或合成的音频上做。
4. 📋 图像 / 视频前端（patch stem + 抽帧池化），用离线教师做对比对齐和蒸馏。
5. 📋 主干升级（RoPE / SSM），掩码事件预训练，主干 int8，按群挂 adapter。
6. 每一步都要先过影子模式门控，才考虑上线。
